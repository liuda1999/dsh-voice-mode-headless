# DSH 语音模式 · 结构与使用说明（v3）

> 整理时间：2026-11-10 12:00
> 环境：macOS，无显示器常驻，通过 SSH 与 Web UI 管理
> 目标：不打开浏览器、不点界面，直接说话即可与智能体对话
> 上游开源项目：https://github.com/qishuilalala/dsh-voice-mode（详见第 13 节）

---

## 0. 一句话现状

语音链路已跑通并常驻：麦克风 → 采集 App → FIFO → 桥接（识别 / 唤醒词 / 会话 / 合成 / 播放）。唤醒词「肥鱼」，语音会话按天轮转（每天第一次对话新建一个当天会话，当天沿用，见 5.5 节），推理走线上模型，音色使用本地 VITS 预设、语速 0.9，开机自动登录后全链路自启。

## 1. 路径与占位符约定

本文不写死任何本机绝对路径与账号信息，统一按下表表示：

| 占位符 | 含义 |
|---|---|

| `<DSH_WEB_DAEMON>` | 系统级 DSH Web 服务 plist 的 Label（位于 `/Library/LaunchDaemons/`） |

## 2. 自启动与"自动启用"状态

### 2.1 结论

| 项目 | 重启后是否自动 | 依据 |
|---|---|---|
| DSH Web 服务 | ✅ 是 | 系统级 LaunchDaemon：`RunAtLoad`、`KeepAlive` 均为 true，`UserName` 指向登录用户 |
| `dsh-voice-mode` 插件启用 | ✅ 是 | profile 的 `package.json` 中 `dsh.profile.bundles` 含 `dsh-voice-mode`；运行时 Inspect 可见条目 `include:voice-mode` 处于已挂载状态 |
| 麦克风采集 `MicAgent` | ✅ 是（依赖自动登录） | 用户级 LaunchAgent（`gui/<UID>`），`RunAtLoad`/`KeepAlive` 均为 true |
| 桥接 `bridge.mjs` | ✅ 是（依赖自动登录） | 同上 |

### 2.2 机制说明

- 本机已开启**系统自动登录**：凭据以系统 `kcpassword` 形式保存，`sysadminctl -autologin status` 显示自动登录用户。FileVault 处于关闭状态，满足自动登录前提。
- 开机流程：自动登录 → 建立 `gui/<UID>` 域 → 系统级 Web 服务启动并挂载插件 → 用户级两个 agent 自动启动 → 麦克风 TCC 授权按 App 的 cdhash 记忆，重启后仍有效。
- **无需每次人工登录或重新授权**；agent 崩溃会被 `KeepAlive` 拉起。
- 代价与注意：登录密码以系统 kcpassword 保存、登录窗口被跳过；若修改登录密码，需重新执行 `sysadminctl -autologin set`，否则自动登录失效。

### 2.3 尝试过但不行的方案

将采集改为**系统级 LaunchDaemon**（`UserName` 设为登录用户）实测失败：日志显示 `auth_status=2`、麦克风授权被拒——麦克风 TCC 授权只在用户登录会话内生效。要绕过必须安装 **PPPC 配置描述文件**（`com.apple.TCC.configuration-profile-policy`）做预授权；当前未采用该方案，改用自动登录解决。

## 3. 架构与一次对话的链路

```
麦克风（系统默认输入设备）
   │
   ▼
MicAgent.app（Swift + AVFoundation）
   │  采集 → 转 16 kHz 单声道 float32
   ▼
FIFO：/tmp/dsh-voice-mic.f32
   │
   ▼
bridge.mjs（Node）
   ├─ 100 ms 分块 + RMS 门控 + 300 ms 预滚
   ├─ sherpa-onnx 流式识别（边听边出字）
   ├─ 段结束再用 SenseVoice 定稿（纠错、补标点）
   ├─ 唤醒词匹配
   ├─ 调 headless profile 生成答复（cwd = <VOICE_WS>）
   ├─ VITS 逐句合成
   └─ afplay 播放 + 三声提示音
   │
   ▼
会话文件：<DSH_HOME>/sessions/--<VOICE_WS 编码>--/<session-id>/session.v4.jsonl.zstd
   └─ 每轮把会话 id 注册进 <DSH_HOME>/storages/workspace.json 的「语音对话」工作区
```

**为什么不是插件原生模式**：`dsh-voice-mode` 的录音在浏览器里（客户端调用 `navigator.mediaDevices.getUserMedia`），宿主端没有任何采集代码。无浏览器方案因此新增了宿主端采集 + 桥接，只复用插件下载的模型与音色表。

**一次对话的判定顺序**
1. 静音 → 不送识别器（空闲 CPU ≈ 0）。
2. 有声音 → 进入语音段，300 ms 预滚保证句首不丢。
3. 连续静音 **2000 ms** → 该段结束（`VOICE_SILENCE_MS` 可调）。
4. 文本以唤醒词开头 → 剥掉唤醒词，剩余部分作为指令。两字唤醒词的规则是「**必须出现在句首、第二个字精确匹配、首字容许同音**」：说「飞鱼…」能唤醒，说「买条鱼」不会。
5. 唤醒词是**最高优先级**：只喊唤醒词时，立刻停掉正在朗读的音频、回「我在」、打开 20 秒命令窗口；**不动正在执行的任务**。
6. 随后的命令若是停止类（停 / 停下 / 停止 / 别做了 / 取消 / 算了 / 不用了 / 等一下，且整句不超过 12 字）→ 立刻终止在跑的任务、停播、回「好的，停了」。
7. 其它命令：任务空闲则立即执行；任务忙则排队，当前轮结束后自动接着处理。
8. 朗读期间只有说出唤醒词才会被打断（回声、咳嗽、噪声都不会截断朗读）。

## 5. 配置参数

### 5.1 桥接参数（可用环境变量覆盖）

| 名称 | 当前值 | 说明 |
|---|---|---|
| `VOICE_WAKE` | `肥鱼` | 唤醒词；两字词末字精确、首字容许同音 |
| `VOICE_SILENCE_MS` | `2000` | 断句静音阈值 |
| `VOICE_RMS` | `0.006` | 说话判定阈值（环境底噪实测 0.0007–0.0032） |
| `VOICE_WAKE_WINDOW` | `20000` | 只喊唤醒词后的免唤醒窗口（毫秒） |
| `VOICE_FOLLOWUP` | `0` | 一轮回答后的免唤醒窗口（0 = 必须叫名字） |
| `VOICE_SPEED` | `0.9` | 合成语速 |
| `VOICE_BARGE` | `0.02` | 保留项（当前以"识别出文本"作为打断条件） |

内部固定：最短语音段 300 ms、最长 15 s、合成切句 ≤60 字、朗读上限 800 字、采集停滞看门狗 12 s、设备探测周期 20 s。

### 5.2 DSH 配置

| 文件 | 条目 | 值 |
|---|---|---|
| `<DSH_HOME>/profiles/web/cordis.patch.yml` | `voice-mode` | `wakeWord`、`autoResume: true`、`allowLan: true`（仅影响浏览器版界面；桥接使用自己的唤醒词） |
| `<DSH_HOME>/profiles/headless/cordis.patch.yml` | `agent-default-model` | `provider: deepseek-official`、`model: deepseek-flash` |
| `<DSH_HOME>/storages/workspace.json` | `<VOICE_WS>` | 工作区标题「语音对话」 |

### 5.3 语音规则（`<VOICE_WS>/AGENTS.md`）

```markdown
# 语音工作区

本目录只用于语音对话。你的每一条回答都会被合成语音直接朗读给用户听，用户看不到屏幕。

## 语音规则
- 只输出口语短句；不要 markdown、列表、编号、代码块、表格、链接、加粗符号、括号注释。
- 单次回答 2 句话以内，除非用户明确要求详细。
- 时间日期用中文口语（如「早上八点半」「十一月十号星期二」），不要写机器时间格式。
- 需要查询信息时直接调用工具，不要把命令、代码、脚本贴在回答里；也不要问"需要我执行吗"，直接执行再回答。
- 工具输出不要复述，只给结论。
- 会话按天轮转：每天第一次对话使用新建的当天会话，当天后续对话沿用；这由宿主侧完成，不要在回答里向用户复述。
- 数字读法自然：金额说"三百二十块"，不要说"320 元整"。
```

### 5.4 噪声与误触发防护

| 防护点 | 做法 | 原因 |
|---|---|---|
| 起音门控 | RMS < 0.006 不进入语音段，也不送识别器 | 环境底噪实测 0.0007–0.0032，阈值留出余量 |
| 最短语音段 | 300 ms 以下不算一句话 | 排除键盘、碰撞等瞬态噪声 |
| 空文本段 | 识别结果为空或只有标点时直接丢弃 | 噪声段常见的产物 |
| 唤醒词位置 | 必须位于句首，且第二个字精确匹配 | 避免「买条鱼」这类句子被误判为唤醒 |
| 短唤醒词容错 | 仅首字允许同音（飞鱼 / 菲鱼 可唤醒） | 兼顾识别偏差与误触 |
| 停止词范围 | 只接受 ≤12 字的短句 | 避免长句恰好以「停」开头就终止任务 |
| 朗读打断 | 只有说出唤醒词才停播 | 扬声器回声曾被识别成插话，导致回复被截断 |
| 采集看门狗 | 3 秒无音频块才重启，且 10 秒内不重复 | 过密的重启会打断启动与授权流程 |

### 5.5 会话轮转规则（补充）

方案基线描述的是固定单一会话；本仓库按运维补充采用**按天轮转**：每天第一次对话新建一个当天会话，当天后续对话沿用，跨天后的第一次对话再新建。

| 时机 | 行为 |
|---|---|
| 每天第一次对话 | 新建一个会话作为当天会话，把新 `sessionId` 写入 `<VOICE_DIR>/session-id.txt`，并按第 3 节既有机制注册进 `<DSH_HOME>/storages/workspace.json` 的「语音对话」工作区 |
| 当天后续对话 | 沿用该会话，保留当天上下文，不新建 |
| 跨天后的第一次对话 | 判定本机本地日期已变化，再新建一个当天会话；旧会话保留可查 |
| 会话被 Web 界面占用写锁 | 仍按第 8、9 节处理（每 5 秒重试），不为解锁而改换会话 |

实现要点：

- 判定放在桥接侧，用**本机本地日期**（如 `YYYY-MM-DD`）与随 `session-id.txt` 保存的日期标记比对，不要用 UTC 或云端时间。
- 新建会话沿用第 10.2 节第 5 步取 `sessionId` 的方式；创建失败时保留旧会话并给出错误提示音，不要静默丢话。
- 本规则只改变会话的产生时机，不改变第 3 节链路、第 5.3 节语音输出规则、第 5.4 节噪声防护，也不改变单轮朗读上限等限制。
- 第 7 节的 `printf '' > <VOICE_DIR>/session-id.txt` 仍可用于立即开一段全新会话（会丢失当前上下文）；正常情况下无需手动执行。

## 6. 模型

- 当前：线上 `deepseek-official / deepseek-flash`。
- 切回本地：把 `<DSH_HOME>/profiles/headless/cordis.patch.yml` 的 `agent-default-model` 改为本地 provider 与模型名，**下一轮立即生效**（每轮都会新起进程，无需重启桥接）。
- 云端鉴权：桥接从 `<DSH_HOME>/.credentials.yaml` 读取对应 API Key 注入运行环境；缺失时语音端表现为错误提示音。
- 识别模型：流式 zipformer（边听边出字）+ SenseVoice（段末定稿纠错，补标点、纠正同音字）。

## 7. 操作手册

```bash
# 查看状态
launchctl print gui/$(id -u)/com.local.dshvoice.mic    | head -5
launchctl print gui/$(id -u)/com.local.dshvoice.bridge | head -5
pgrep -fl "dsh-voice-agent|bridge.mjs"
tail -f <VOICE_DIR>/bridge.log

# 重启采集 / 桥接
launchctl kickstart -k gui/$(id -u)/com.local.dshvoice.mic
launchctl kickstart -k gui/$(id -u)/com.local.dshvoice.bridge

# 更换音色（可选预设：suyingxue / gunian / fushiyu / bingjiao / bazong）
echo gunian > <VOICE_DIR>/voice.txt
launchctl kickstart -k gui/$(id -u)/com.local.dshvoice.bridge

# 调整语速或断句停顿：在 plist 的 EnvironmentVariables 中加入
#   VOICE_SPEED=0.9  VOICE_SILENCE_MS=2000
# 然后重启桥接

# 开一段全新会话（会丢失当前上下文；正常情况下按 5.5 节每天自动轮转，无需手动）
printf '' > <VOICE_DIR>/session-id.txt
```

## 8. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 完全没反应，日志无语音段记录 | 采集停止（设备休眠、音频路由切换） | 看门狗 12 s 自动重启采集；手动 kickstart 采集 agent |
| 音量峰值恒定在极低值 | 麦克风无输入（设备选错、输入音量为 0） | 检查系统默认输入设备与输入音量 |
| 喊唤醒词没反应 | 识别偏差，或不在 20 秒窗口内 | 已有定稿纠错；必要时改用 3 字以上唤醒词 |
| 话没说完就被执行 | 停顿时间不足 | 已放宽至 2 秒；仍不够则调大 `VOICE_SILENCE_MS` |
| 日志持续 `session locked, retry` | Web 界面打开了该语音会话并持有写锁 | 关闭该会话；桥接每 5 秒重试，不会新建会话 |
| 侧栏看不到新会话 / 内容不实时 | 宿主只在启动时加载会话列表，且不监听文件变化 | 重启 Web 服务，或刷新页面 |
| 朗读含糊 | 合成音质与语速 | 语速已降至 0.9；可换在线音色或其它本地预设 |

## 9. 已知限制

1. 界面非实时：会话文件由桥接侧进程写入，宿主不监听文件，界面只在打开或刷新时读取。
2. 侧栏会话列表在 Web 服务启动时载入，之后新增的会话需重启服务才会出现。
3. 在界面打开语音会话会给它加写锁，与语音写入冲突（桥接会一直重试，不更换会话）。
4. 单轮朗读超过 800 字会被静默截断（会话记录不受影响）。
5. 朗读中的打断需等 2 秒静音（与断句阈值共用）。
6. 蓝牙耳机在播放期间麦克风可能被系统切走，导致朗读期打断失效。
7. 模型切换没有运行时开关，需改 profile 配置。
8. 冷启动依赖系统自动登录（见第 2 节）。
9. 可清理的遗留物：早期隔离 home 目录、`bridge.mjs.bak*` 备份、已停用的查看页脚本。

## 10. 从零部署（拉到插件包之后怎么做）

这一节回答："拿到 `node_modules/dsh-voice-mode` 这个包 / 这份仓库后，怎么一步步做成现在这台机器的效果"。

### 10.1 前置条件

- macOS 12+，Node 24（本项目用 nvm 管理），`dsh` CLI 可用，已有 `web` profile。
- 至少一个可用麦克风；需要有**一次性**的图形登录能力（麦克风授权只能人工点一次）。
- 网络：能访问 npm registry；`huggingface.co` 可能不可达，需要 `hf-mirror.com` 兜底。

### 10.2 部署步骤

**第 1 步：安装插件到 profile**

```bash
dsh plugin --profile web add dsh-voice-mode
```

校验：`<DSH_HOME>/profiles/web/package.json` 的 `dsh.profile.bundles` 应包含 `dsh-voice-mode`；Web 服务起来后 `GET /voice-mode/config` 返回 200。

**第 2 步：下载并校验模型（有坑）**

```bash
cd <DSH_HOME>/profiles/web/node_modules/dsh-voice-mode
node scripts/prefetch.mjs          # 默认缓存到 ~/.cache/dsh-voice-mode/models
```

已知问题：`prefetch.mjs` 的 Kokoro 主模型与 `lexicon-zh.txt` 按仓库默认分支抓取，而运行时按**固定版本号**校验（int8 与 fp32 各一个 revision），所以会出现「下载失败 / 校验失败」或镜像 429。

处理办法：
1. 从 `prefetch.mjs` 里读出运行时约定的 revision 与 SHA256；
2. 按 `https://<镜像>/csukuangfj/<repo>/resolve/<revision>/<file>` 直接下载这 4 个文件到 `<MODELS>/csukuangfj/<repo>/`；
3. 逐文件重算 SHA256 与清单比对，期望 **32/32 全通过**（`check-models.mjs` 就是为此写的，见 10.4）；
4. Kokoro 的 `espeak-ng-data` 支持文件约有 355 个，prefetch 被限流时可用 HF 的 tree API 逐个补齐（`fetch-espeak.mjs` 是同样的思路）。

**第 3 步：建立语音工作区**

```bash
mkdir -p <VOICE_WS>
# 把第 5.3 节的语音规则写入 <VOICE_WS>/AGENTS.md
```

然后在 `<DSH_HOME>/storages/workspace.json` 里注册工作区记录。**必须包含** `path`、`title`、`sessionIds`、`createdAt`、`updatedAt` 五个字段——缺 `updatedAt` 会导致 `workspaceRegistry` 启动失败，表现为侧栏整个会话列表空白（本机实测踩过）。

**第 4 步：编译并授权采集 App**

目录结构：

```
MicAgent.app/Contents/Info.plist
MicAgent.app/Contents/MacOS/dsh-voice-agent
```

`Info.plist` 关键键：`CFBundleIdentifier`、`CFBundleExecutable`、`LSUIElement=true`（后台应用、无 Dock 图标）、`NSMicrophoneUsageDescription`。

```bash
swiftc -O mic_agent.swift -o MicAgent.app/Contents/MacOS/dsh-voice-agent
codesign --force --deep -s - --identifier <bundle-id> MicAgent.app
open -a MicAgent.app       # 触发系统麦克风授权弹窗，点「允许」
```

注意：
- 授权只能一次性人工点（后台进程不会弹窗）；授权按 App 的 cdhash 记忆。
- **重新编译会改变 cdhash**，需要重新授权，所以部署完成后不要再改这个二进制。

**第 5 步：部署桥接**

```bash
cp bridge.mjs <VOICE_DIR>/ && node --check <VOICE_DIR>/bridge.mjs
```

部署前确认常量：FIFO 路径、两个模型目录、唤醒词、断句阈值、语速、音色文件名。

首次使用要先有一个会话 id：先跑一次 `dsh --profile headless --json "<任意问题>"` 拿到 `sessionId`，写入 `<VOICE_DIR>/session-id.txt`。当前策略按 5.5 节**每天首轮新建当天会话、当天沿用**；会话 id 缺失且无法创建时会报错误提示音，不静默丢话。

**第 6 步：配置 DSH**

- `web` profile：`voice-mode` 条目设 `wakeWord`、`autoResume: true`、`allowLan: true`（后者让局域网浏览器能调语音接口，默认仅 loopback）。
- `headless` profile：`agent-default-model` 决定语音用哪个模型（线上 / 本地），改完下一轮即生效。
- 云端模型需要把 API Key 放进 `<DSH_HOME>/.credentials.yaml` 的 `refs` 下；桥接会自动读取注入运行环境。

**第 7 步：安装两个用户级 LaunchAgent**

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.local.dshvoice.mic.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.local.dshvoice.bridge.plist
```

plist 关键项：`RunAtLoad`、`KeepAlive`、`StandardOutPath`/`StandardErrorPath`；桥接建议用绝对 node 路径并在 `EnvironmentVariables` 里给出 `PATH`。

**第 8 步：让重启后不用人工登录**

- Web 服务必须是**系统级 LaunchDaemon**（`/Library/LaunchDaemons/`，`RunAtLoad` + `KeepAlive` + 指定 `UserName`）。
- 采集与桥接是**用户级 agent**，只在用户登录会话内运行；因此需要开启系统自动登录（前提：FileVault 关闭）：

```bash
sudo sysadminctl -autologin set -userName <user> -password <password>
sudo sysadminctl -autologin status        # 应显示自动登录用户
```

- 不要试图把采集改成系统级 LaunchDaemon：麦克风 TCC 只在用户会话内生效，实测会得到 `auth_status=2`（拒绝）。

**第 9 步：验收**

1. `pgrep -fl "dsh-voice-agent|bridge.mjs"` 两个进程都在；
2. `<VOICE_DIR>/mic-agent.log` 里 `frames` 持续增长、`peak` 不为 0；
3. `<VOICE_DIR>/bridge.log` 每 4 秒有电平行；
4. 说唤醒词 → 听到「我在」→ 说任务 → 正常答复；
5. `cat <VOICE_DIR>/session-id.txt` 同一天内前后不变；跨天后的第一次对话应变为新的当天会话 id（见 5.5 节）。

## 13. 来源与上游开源项目

本方案文档基于以下开源项目生成。文中反复出现的 `node_modules/dsh-voice-mode`（即 profile 的 `node_modules/dsh-voice-mode`，由 `dsh plugin --profile web add dsh-voice-mode` 安装）指的就是该项目发布到 npm 的包：

| 项目 | 链接 |
|---|---|
| GitHub 仓库（上游） | https://github.com/qishuilalala/dsh-voice-mode |
| npm 包 | https://www.npmjs.com/package/dsh-voice-mode |
| Issues | https://github.com/qishuilalala/dsh-voice-mode/issues |
| Releases | https://github.com/qishuilalala/dsh-voice-mode/releases |

- 项目全称：DSH（DeepSeek Harness）全双工语音插件；MIT 许可证，维护者 qishuilalala。npm 包当前版本 0.7.35（2026-11-10 查询）。
- 上游插件的原生形态是**浏览器端**语音模式：客户端 `navigator.mediaDevices.getUserMedia` 采集、流式识别入可编辑草稿、按句朗读 + 实时字幕、开口即打断、可选唤醒词。
- 本文档描述的是**无浏览器 / 无显示器常驻**的宿主端方案：不使用上游的浏览器 UI，仅复用其模型下载脚本（`scripts/prefetch.mjs`）、识别与合成模型、音色表与设置页；采集 App、FIFO 音频管道、桥接、LaunchAgent 自启、headless 会话接入均为在此之上自建的链路（详见第 3、10 节）。
- 本节仅作来源追溯与查证补充，不改动本文档的技术实现与参数；会话轮转规则的补充见第 5.5 节与第 12 节阶段 18。
